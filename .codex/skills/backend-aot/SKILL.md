# Native AOT API

## 작업 범위

- 질문·설명·검토·계획 요청에서는 읽기와 분석만 수행합니다. 아래 구현 지침은 검토 기준으로 사용합니다. 산출물을 생성하는 검증은 명시적으로 실행을 요청받은 경우에만 수행하며, 검증 요청 자체는 소스 수정 권한이 아닙니다.
- 구현·수정을 요청받았을 때만 해당 범위와 필수 연관 부분을 변경합니다. 무관한 AOT 경고 해결, 리팩터링, 설정·패키지 변경을 추가하지 않습니다.
- 원격 배포, HTTP·AD 요청, DB 쓰기는 절대로 실행하지 않습니다. 관련 코드는 작성할 수 있지만 실행은 사용자에게 맡깁니다. 검증 요청도 이 금지의 예외가 아닙니다.

## 기술 지침

1. 프로젝트의 Target Framework가 .NET 10이고 `PublishAot`가 활성화되었는지 먼저 확인합니다.
2. 런타임 리플렉션, `dynamic`, 런타임 코드 생성을 사용하지 않습니다.
3. JSON 요청·응답 타입을 `JsonSerializerContext`에 등록하고, 필요한 `JsonTypeInfo<T>` 오버로드를 사용합니다.
4. 엔드포인트는 이름 있는 정적 메서드에 매핑합니다. 오류 응답과 검증은 프로젝트의 기존 규격을 우선합니다.
5. 새 라이브러리를 추가하기 전 AOT·트리밍 호환성을 확인합니다.
6. 구현·수정 후에는 금지 작업이 발생하지 않는 관련 로컬 테스트만 실행합니다. AOT 호환성에 영향을 주는 변경이나 명시적인 게시 검증 요청에서는 `dotnet publish -c Release /p:PublishAot=true`에 해당하는 로컬 산출물 생성을 검토하되, 패키지 복원·다운로드와 실행 훅까지 확인하여 금지 작업 없이 실행할 수 있는 경우에만 수행합니다. 이를 확인할 수 없으면 검증을 사용자에게 맡기고 미실행 이유를 보고합니다. 변경으로 발생한 경고는 해결하고, 무관한 기존 경고는 보고합니다. 원격 배포는 절대로 수행하지 않습니다.

## C# 코드 스타일

- 읽기 쉬운 길이의 메서드 선언과 호출은 한 줄로 유지합니다. 인수 개수만으로 줄바꿈하지 않습니다.
- 로그 메시지를 줄 길이 때문에 문자열 연결로 나누지 않습니다. 기존의 구조화된 로깅 방식을 유지합니다.
- 긴 람다나 중첩 표현식은 가독성에 필요한 만큼 줄바꿈합니다. 무관한 코드의 포맷은 변경하지 않습니다.
- 프로젝트 포맷터 설정과 충돌하면 설정을 임의로 바꾸지 않고 알립니다.

```csharp
MethodA(a, b, c);
logger.LogInformation("Order {OrderId} completed with status {Status}", orderId, status);
```
