# 장애 진단

1. 오류 메시지, 재현 절차, 영향 범위, 발생 시각, 관련 배포·설정 변경을 수집합니다.
2. 입력 검증, 데이터 접근, 외부 HTTP 호출, Worker 실행, AOT 게시 단계 중 실패 경계를 좁힙니다.
3. 구조화된 로그의 상관관계 ID와 예외를 사용해 원인을 확인합니다. 비밀 정보와 요청 본문은 로그에 기록하지 않습니다.
4. 추측으로 재시도·설정 변경·의존성 변경을 반복하지 않습니다. 가설마다 최소 재현 또는 읽기 전용 증거를 확보합니다.
5. 수정 후에는 원인, 변경 내용, 재현 방지 검증을 기록합니다.
6. 시작·성공 같은 흐름성 로그 대신 오류, 재시도 소진, 데이터 상태 변화, 성능 임계치 초과를 기록합니다.
