# 백엔드 캐싱

1. 캐시할 조회, 허용 가능한 최신성, 무효화 주체를 먼저 정의합니다. 불명확하면 캐시를 추가하지 않습니다.
2. 프로젝트에 이미 있는 캐시 추상화와 저장소를 사용합니다. 새 인터페이스나 공급자는 사용자 승인 없이 도입하지 않습니다.
3. 키는 `도메인:조회:식별자` 형식으로 일관되게 구성하고, 모든 CUD 작업에서 관련 항목·목록 캐시를 무효화합니다.
4. TTL은 데이터 특성에 맞춰 설정합니다. 무한 TTL과 캐시만을 정답으로 하는 설계를 피합니다.
5. 단일 프로세스 경합에는 로컬 동기화를, 다중 인스턴스 경합에는 캐시 공급자의 원자 연산 또는 분산 수단을 사용합니다.
6. 캐시 값이 JSON이면 해당 타입을 JSON 소스 생성기에 등록합니다.
7. 조회 hit/miss 같은 흐름성 정보 로그는 기본적으로 남기지 않습니다. 무효화 실패나 정합성 위험만 구조화해 기록합니다.
